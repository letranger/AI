1. 什麼是 vibe coding

1.1. 一句話定義

你用 中文描述 想要的東西，AI 負責寫程式；你負責 出主意、驗收、給回饋 。 這個詞是 OpenAI 共同創辦人 Andrej Karpathy 在 2025 年初提出的：

"Fully give in to the vibes… forget that the code even exists." （完全順著感覺走……甚至忘記程式碼的存在。）

但我們不會真的「忘記程式碼存在」——上半場講過： 程式碼也會有幻覺 ， 會驗收的人才開得快。

1.2. 三個常見誤解

誤解 真相
「就是讓 AI 幫我寫程式」 是 你 描述需求、驗收、微調——AI 是你 意志的延伸 ，不是替代
「就是不用學程式了」 打字、查語法交給 AI；但 想清楚、看得懂、會驗收 更重要了
「那是不會寫程式的人在用的」 資深工程師用得更兇——它是每個人都該會的基本功，像會用 Google 一樣

1.3. 工具: Web-based vs Terminal-based

你們可能已經用過 ChatGPT 網頁版寫程式：貼題目 → 複製程式碼 → 貼到檔案 → 存檔 → 執行 → 出錯 → 把錯誤貼回去……一直「當人肉傳令兵」。

Terminal 版的差別：AI 就住在你的專案資料夾裡， 自己動手 。

比較 Web-based（ChatGPT 網頁） Terminal-based（Claude Code 等）
寫檔案 你複製貼上 AI 直接建立、修改檔案
執行程式 你自己跑 AI 自己跑、自己看結果
看錯誤 你貼給它 AI 自己讀錯誤訊息、自己修
改多檔 很痛苦 AI 一次改好幾個檔案
你的角色 傳令兵＋驗收 指揮官＋驗收

1.4. 你還是要會的三件事

  1. 說清楚需求 ：對象是誰、要做什麼、長什麼樣子。
  2. 驗收 ：打開來用用看，判斷「這是不是我要的」。
  3. 看懂大意 ：不必會寫每一行，但要能看懂 AI 說它做了什麼。

1.5. 什麼時候適合、什麼時候不適合

  • 適合：小工具與自動化腳本、做原型、幫既有程式補文件、探索別人的程式碼 ——今天的零用錢程式就是典型場景。
  • 不適合： 你完全無法驗收結果 的領域（例如醫療、金融的核心邏輯）。 看不懂又沒能力測，那不是在 coding， 是在賭 。

1.6. 五條守則（上半場 Part 13 的複習）

  1. API key 只放後端環境變數：不進前端程式碼、不貼進聊天視窗。
  2. AI 寫的程式要 跑過、看懂再收下 ——程式碼也會有幻覺。
  3. 小步快跑：一次只改一件事，改完馬上測。
  4. 個資、照片、帳密不丟進 AI。
  5. 免費額度有限：省著用、善用免費工具。

2. 有哪幾種可用工具

2.1. 主要 CLI 工具

工具 公司 安裝 需要的帳號／費用
Claude Code Anthropic npm install -g @anthropic-ai/claude-code Claude Pro 訂閱（月費）或 API 付費
Codex CLI OpenAI npm install -g @openai/codex ChatGPT 帳號（Plus 訂閱）
Gemini CLI Google npm install -g @google/gemini-cli API 金鑰（免費 Google 登入已終止）
Antigravity CLI Google 一行安裝指令（見前置作業） 本課示範工具 ：貼金鑰或 Google 帳號登入

⚠ 挑工具前的背景：Gemini CLI 的「Sign in with Google」免費登入已於 2026/6/18 被 Google 終止，免費額度移到接班的 Antigravity CLI —— 所以 本課直接用 Antigravity CLI （指令叫 agy ）。

課堂做法：啟動 agy 後，把 老師發的 API 金鑰 直接貼進認證欄即可。 課程結束後金鑰會作廢， 不要 把金鑰貼到任何網頁或程式碼裡。 家裡有 ChatGPT Plus 的同學可以改用 Codex CLI ，操作邏輯完全相同。

2.2. 共同前置作業

  1. 安裝 Node.js：到 nodejs.org 下載 LTS 版，一路下一步。
  2. 打開終端機：
    • macOS：Spotlight 搜尋「終端機」（Terminal）
    • Windows：開始選單搜尋「PowerShell」

  3. 確認安裝成功： 

       node -v        # 出現 v22.x 之類的版本號就 OK
   npm -v

  1. 安裝本課工具 Antigravity CLI（一行指令，不是 npm 套件）： 

       # macOS / Linux
   curl -fsSL https://antigravity.google/cli/install.sh | bash
   # Windows（PowerShell）
   irm https://antigravity.google/cli/install.ps1 | iex

    裝好後 重開一個終端機視窗 ，指令叫 agy 。 （Node.js 不是給 agy 用的——之後上架網站的 npx vercel 會用到。）

2.3. 如何申請金鑰

  1. 開 aistudio.google.com/apikey，登入 Google 帳號。
  2. 按「Create API key」→ 複製那串 AIza... 開頭的金鑰。
  3. 免費層 不用綁信用卡 ：約每天 250 次請求、限 Flash 系列模型，課堂夠用。

注意：AI Studio 的服務條款要求年滿 18 歲，學生的學校帳號通常申請不了 ——所以課堂用 老師課前準備好的金鑰 ，回家想自己玩再用家長帳號申請。

拿到金鑰後 不用設定任何環境變數 ：啟動 agy ， 在認證畫面把金鑰直接貼進認證欄就完成登入。

2.4. 本課示範工具：Antigravity CLI

2.4.1. 啟動與認證

安裝（見「共同前置作業」）完成後，進專案資料夾啟動： 

cd money-app
agy

第一次啟動會依序問你：配色、顯示模式、要不要信任這個資料夾， 接著出現認證畫面—— 把老師發的金鑰貼進認證欄 就完成了。 （自己有成年 Google 帳號的話，也可以改用帳號直接登入， 走免費 Individual 方案，月費 $0，還能選到 Claude、gpt-oss 等模型。）

補充： agy 是 Gemini CLI 的官方接班者，保留了同一套操作習慣—— 中文描述任務、動作前徵求你同意、斜線指令、 GEMINI.md 班規檔照讀 （連 Claude/Codex 生態的 AGENTS.md 也一併支援）。

2.4.2. 每日能用多少額度？   noslide

agy 的使用額度取決於你綁定的 Google AI／Google Cloud 方案層級：

方案層級 額度說明 備註
免費層級（Free Tier） 每天約 1,500 次請求（以 Gemini API 免費層為例）、每分鐘約 15 次（RPM） 短時間連續丟大量程式碼或長檔案，可能觸發 429 Too Many Requests （速率限制）
付費／Google Cloud（Vertex AI） 彈性按量計費（Pay-as-you-go） 額度取決於 GCP Console 設定的 API Quota 上限，日常使用基本不受小額限制
Google 訂閱方案 依 Gemini Advanced／Workspace 等訂閱層級提供高上限用量 適合高強度的每日開發與大專案維護

課堂小提醒：撞到 429 不是壞掉，是 說話太快 ——等一分鐘再繼續， 或把一次塞太多檔案的 prompt 拆小。

Google 官方的正式說法 （官方不公布確切數字，只給定性描述）：

  • 免費（Individual）方案：定價頁寫「Basic weekly rate limits」——官方部落格 解釋是「改為較寬鬆的 以週為單位 的速率上限，減少專案做到一半突然撞牆」 （原文：/"we've shifted to a larger, weekly based rate limit to minimize hitting rate limits quickly"/）。
  • Google AI Pro／Ultra 訂閱：「最高、最寬鬆的速率上限， 每 5 小時刷新 一次配額」 （原文：/"quotas that refresh every five hours"/），且享有優先存取。
  • 各方案 都能用 Gemini 3 Pro ，差別只在額度多寡與刷新頻率，不在模型等級。

也就是說：上表的「每天 1,500 次」是 AI 自己回答時 借用了 Gemini API 免費層 的數字，並不是 Antigravity 的官方額度——官方對 agy 免費層只承諾 「週制基本額度」。實際夠不夠用，開工前用一天實測最準。

2.5. 三個工具的共同操作模式

  1. cd 進你的專案資料夾，啟動工具（ agy / claude / codex ）。
  2. 用中文打字描述你要做的事。
  3. AI 提議動作（建立檔案、執行指令），問你 要不要同意 。
  4. 看一眼它要做什麼 → 同意 → 它做完會回報。
  5. 你去驗收，再下一個指令。

幾個通用的小技巧：

  • / 開頭是給 工具本身 的指令（不是給 AI 的）： /help 指令總覽、 /stats 看額度用量、 /quit 離開；卡住按 Esc 或 Ctrl-C 中斷。
  • @檔名 把檔案內容附給 AI（ @index.html 幫我解釋這段 ）； !指令 不問 AI 直接跑 shell（ !ls ）。
  • 這些工具都有「全自動同意」模式—— 課堂禁用 ： 上半場才講過 AI 會幻覺，全自動＝閉著眼睛開車。

2.6. Terminal 生存指令包（會這六個就夠了）

pwd            # 我現在在哪個資料夾？
ls             # 這裡有什麼檔案？
cd 資料夾名     # 進入資料夾
cd ..          # 回上一層
mkdir 名字      # 建新資料夾
open index.html   # macOS 用預設瀏覽器開檔（Windows 用 start index.html）

3. Vibe coding 使用流程：以開發網頁為例

今天的實作目標：做一個 「我的零用錢管理程式」 單頁網站—— 一步一步長出功能，最後真的上線給別人用。 每一步都是同一個循環： 說需求 → AI 動手 → 打開驗收 → 滿意就存檔 。

3.1. Step 0：開專案資料夾＋立班規

mkdir money-app
cd money-app
agy

為什麼要先開資料夾？ AI 會在「目前資料夾」裡動手，開新資料夾＝給它一個 乾淨的工作間，它不會誤改到你其他東西。

進去後的第一件事：建「班規」檔 GEMINI.md ——放在專案資料夾裡的這個檔， agy 每次啟動都會自動讀，等於 不用每次重講的長期規則 （Claude Code 的同款檔案叫 CLAUDE.md ，Codex 叫 AGENTS.md ， agy 都認）。 直接請 AI 代勞： 

幫我建立 GEMINI.md，規則：一律繁體中文回答；整站只用一個 index.html，
不用框架；每次修改後用一句話總結；要裝任何套件前先問我。

3.2. Step 1：外觀——先把殼做出來

3.2.1. 動手前：先聊需求，不要寫程式

好導演不會一句話交代整部電影。第一個訊息先把 AI 當 諮詢顧問 ， 並且 要求它反問你 ： 

我想做一個給高中生自己用的零用錢管理網頁。
先不要寫程式，先反問我三個問題，幫我釐清需求。

它可能會問：要不要分類別？資料存哪裡？要不要設額度上限？—— 你回答完，需求就自己長清楚了，正好變成下一步 prompt 的素材。

3.2.2. 第一個 prompt

壞的開場： 

幫我做一個記帳網站

好的開場（目的＋對象＋版面＋風格＋技術限制）： 

幫我做「我的零用錢管理程式」單頁網站，給高中生自己用的。
版面：最上方顯示「本月支出總額」（先寫 0 元），中間是支出列表
（先放三筆假資料），下方有一顆「新增支出」按鈕（先不用有功能）。
風格：清爽、手機上好操作。
技術：只用一個 index.html，CSS 和 JavaScript 都寫在裡面，不要用任何框架。

最後一行很重要—— 限制越清楚，AI 越不會自作主張 裝一堆你看不懂的東西。 「先放假資料、按鈕先不用有功能」也是重要技巧： 先看到樣子，再談功能 。

3.2.3. 驗收

做完馬上驗收，不要只回「好」， 打開看 ： 

open index.html      # Windows: start index.html
  • [ ] 版面跟你想的一樣嗎？
  • [ ] 手機寬度好讀嗎？（瀏覽器視窗拉窄看看）
  • [ ] 有沒有它自己加的、你沒要求的東西？

3.3. Step 2：輸入支出

把「新增支出」做成真的：按下去出現輸入格（金額、項目名稱），
送出後加進列表，本月總額同步更新。
資料存在 localStorage，重新整理頁面後不會不見。

不懂 localStorage？ 當場問它 ——這是 vibe coding 最被低估的功能， 它同時是你的家教： 

localStorage 是什麼？用高中生聽得懂的方式解釋你剛剛怎麼用它。

驗收重點：新增幾筆 → 重新整理 → 資料還在嗎？

3.4. Step 3：加類別

新增支出時可以選類別：飲食、交通、娛樂、學用品、其他。
列表每一筆顯示類別，不同類別用不同顏色的小標籤。

一次只加一個功能 ：不要把類別、統計、額度一口氣全丟給它—— 改壞了你會不知道是哪一個造成的。

3.5. Step 4：加統計

加一個「本月統計」區塊：各類別的小計和佔比，
用簡單的橫條圖呈現（不要用圖表套件，用 div 的寬度畫就好）。

「不要用圖表套件」呼應了 Step 0 寫進 GEMINI.md 的班規（「不用框架、 裝套件前先問我」）——多裝一個套件＝多一個你看不懂的黑盒子。

3.6. Step 5：每月零用錢額度

加上「每月零用錢額度」設定（例如 2000 元），
最上方顯示：剩餘額度 ＝ 額度 － 本月總支出。
剩餘不到兩成時變橘色；超支時變紅色並顯示「本月已超支」。

驗收：故意記帳記到超支，顏色真的有變嗎？

3.7. Step 6：存檔點（版本控制）

每完成一個 Step，就值得請 AI 存一個「進度存檔」： 

幫我 git init 並把目前的版本 commit，訊息寫「零用錢程式：基本功能完成」

之後改壞了隨時可以回來。不會 git 沒關係—— AI 會 ，你只要記得喊存檔。

存檔前多問一句，還能抓到 它偷偷改的東西 ： 

commit 之前，先用 git diff 總結這次改了哪些檔案的哪些地方。

你說「改 A」它順手動了 B、C，畫面上看不出來，diff 一眼就看到—— 這是驗收的最後一道網。

3.8. 三個保命口訣

  1. 先談清楚，再動手 ：談需求、談畫面、談步驟，最後才寫程式。
  2. 小步快跑 ：一次只做一件事，做完就驗收。
  3. 看不懂就停 ：AI 寫出你看不懂的東西，立刻問清楚，不要想著 「之後再說」——之後永遠不會再說，出了 bug 你也救不回來。

3.9. 接下來

程式「能用」了，但還差三步才算「完成」：

  1. 禁得起亂輸入（負數、0、天文數字）→ 下一章「除錯」
  2. 讓 AI 給你省錢建議（串 LLM API）→ 「串接 API」章第二部份
  3. 上線給別人用 → 「上架」章

3.10. Prompt 技巧對照表

情境 壞 prompt 好 prompt
起步 幫我做個網站 做「XX」單頁網站，給 OO 看，內容有 A、B、C，只用一個 html
修改 弄好看一點 標題改深綠底白字、內文行距加大
修改 改一堆（列 10 項） 一次一件事，改完驗收再下一件
不滿意 不對，重做 我要的是 X，你做成了 Y，請往 X 的方向改

4. Vibe coding 的除錯

程式一定會壞， 壞了不是你的問題，是流程的一部分 。

4.1. 網頁壞掉的第一現場：開發者工具

瀏覽器按 F12 （或右鍵 → 檢查）→ 切到 Console 分頁。 紅色的字＝錯誤訊息＝ 給 AI 的線索 。

4.2. 三種餵錯誤的方式（由好到普通）

  1. 全文照貼 ：把 Console 的紅字整段複製，貼進終端機： 

       網頁按下按鈕沒反應，Console 顯示這個錯誤，請修好：
   Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
       at index.html:52
  2. 預期 vs 實際 ：「我預期按下『查詢』會顯示天氣，實際上畫面完全沒變化， 也沒有錯誤訊息。」
  3. 叫它自己查 ：「你自己打開 index.html 檢查為什麼按鈕沒綁到事件， 需要的話加 console.log 找問題。」——terminal 工具的強項，它真的會去讀檔案。

4.3. 除錯的節奏

  • 修一次 → 測一次。還是壞的就把 新的 錯誤貼回去（錯誤訊息會變！）。
  • 同一個問題修了 三次 還在鬼打牆 → 換策略：
    1. 換個說法重新描述問題（常常是你們雞同鴨講）。
    2. 「把這個功能整段砍掉，重寫一個最簡單的版本。」
    3. 回到上一個存檔點：「git 回到上一個 commit。」
  • AI 說「修好了」 不等於 修好了。永遠以你的驗收為準。

4.4. 課堂演練 A：弄壞再修（讀錯誤訊息）

故意把 index.html 裡某個 getElementById 的名字改錯一個字母， 存檔重整 → 看 Console 出現什麼 → 照上面的方式讓 AI 修回來。 （體會一次完整的「壞掉 → 讀錯誤 → 餵 AI → 驗收」循環。）

4.5. 課堂演練 B：亂輸入大賽（邊界測試）

除錯不只是修紅字—— 使用者亂用而程式照單全收 ，也是 bug。 拿你的零用錢程式，故意輸入這些：

亂輸入 現在會發生什麼？ 你希望發生什麼？
-100 大概照收 拒絕——負支出等於在賺錢？
0 大概照收 拒絕——0 元的支出沒有意義
999999999 大概照收 提示——一次花九億零用錢？
abc 、空白 可能變 NaN 拒絕非數字，給出提示

Console 完全沒紅字，但這些都是問題——這叫 需求缺口 ： 你沒說，AI 就沒做。把驗收結果變成下一個 prompt： 

幫金額輸入加上驗證：只接受 1 到 10000 之間的整數，
不合法時在輸入框下方顯示紅字提示，不要用 alert 彈窗。

（「不要用 alert」——彈窗會打斷操作，好的提示是就地顯示。這種 使用體驗的細節，AI 不會自動幫你想，要 你 當產品經理。）

5. 如何為 web 串接 API

5.1. API 是什麼

一句話： 別人寫好的服務，你的網頁用網址去要資料 。 瀏覽器裡的 JavaScript 用 fetch(網址) 要資料，對方回傳 JSON（一種文字格式的資料）。

本章分兩部份：先串 一般 API （查天氣——資料是現成的、查表就有）， 再串 LLM API （讓你的網頁裡真的有 AI——回答是即時生成的）。 兩者的做法差很多，關鍵就在「要不要金鑰」。

5.2. 第一部份：串接一般 API——以查詢天氣為例

5.2.1. 先玩免金鑰的：Open-Meteo 天氣

你們「溫室植栽專家系統」首頁的天氣就是用它——免註冊、免金鑰、可直接從網頁呼叫。 在瀏覽器網址列直接貼這串（麥寮的經緯度）： 

https://api.open-meteo.com/v1/forecast?latitude=23.75&longitude=120.25&current=temperature_2m,relative_humidity_2m

看到回傳的 JSON 了嗎？那就是 API 的全部—— 一個網址，換一包資料 。

5.2.2. 實作：幫零用錢程式加「美金匯率」小卡

換一個跟錢有關的免金鑰 API——Frankfurter（歐洲央行匯率，免註冊）。 先在瀏覽器網址列試試： 

https://api.frankfurter.dev/v1/latest?base=USD&symbols=TWD

然後下 prompt： 

在統計區下方加一個「美金匯率」小卡：顯示 1 美元等於多少台幣，
並把本月總支出換算成美元一併顯示。
用 Frankfurter API（免金鑰）：
https://api.frankfurter.dev/v1/latest?base=USD&symbols=TWD
用 fetch 取得資料，載入中要顯示「載入中…」，失敗要顯示「匯率暫時無法取得」。

注意最後一行： 要求處理「失敗」的情況 。網路會斷、API 會掛， 好的網頁不能因此整個爆掉——這也是驗收項目之一（把 Wi-Fi 關掉試試看）。

5.3. 第二部份：串接 LLM API——讓網頁裡真的有 AI

5.3.1. LLM API 跟一般 API 哪裡不一樣？

比較 一般 API（Open-Meteo） LLM API（Gemini／Groq）
回傳內容 現成資料，查表就有 即時生成 的文字，每次可能不同
金鑰 這類公共服務常免金鑰 一定要金鑰
費用 免費 有免費額度，刷爆要錢
呼叫位置 前端直接 fetch 必須經過自己的後端 （藏金鑰）
回應速度 快（毫秒） 慢（秒級），介面要有「思考中…」

5.3.2. 金鑰規則：LLM API 絕不能從前端直接呼叫

金鑰絕對不能寫在前端網頁裡 ——網頁的原始碼人人看得到， 金鑰被抄走＝別人刷爆你的額度。

正確做法（你們的「溫室植栽專家系統」就是這樣）： 

瀏覽器 → 你自己的後端（Vercel serverless function）→ 拿著金鑰去呼叫 LLM API
                     ↑ 金鑰放在後端的「環境變數」裡，前端永遠看不到

對 AI 下指令時直接講規則： 

幫我加一個 serverless function 來呼叫 XXX API，
金鑰用環境變數 XXX_API_KEY 讀取，絕對不要出現在前端程式碼裡。

5.3.3. 實作：加「省錢小軍師」——問 AI 如何節省開支

目標：按一顆「幫我省錢」按鈕，把 本月支出統計＋你的問題 送給 LLM， 拿回針對你實際花費的具體建議。 用 Groq 的免費 API（跟你們「溫室植栽專家系統」的生成端同一家）。prompt： 

幫零用錢程式加「省錢小軍師」功能：
1. 前端：統計區旁加一顆「幫我省錢」按鈕，按下後把本月各類別
   支出小計和問題「我如何節省開支？」送到我們自己的 /api/advice，
   等待時顯示「小軍師思考中…」，失敗顯示「暫時無法給建議」。
2. 後端：建立 api/advice.js（Vercel serverless function），
   收到資料後呼叫 Groq API 的 llama-3.3-70b-versatile 模型，
   金鑰從環境變數 GROQ_API_KEY 讀取，絕對不要出現在前端。
3. system prompt 設成「你是理財小老師，根據支出數據，
   給高中生三條具體、做得到的省錢建議，用繁體中文，
   資料不足就說資料不足，不要瞎猜」。

這裡藏著一個 LLM 應用的核心觀念： 把資料跟問題一起送進去 。 只問「我如何節省開支」，AI 只能講幹話；附上「飲食 1,200、 娛樂 800、交通 300」，它才能說出「你的飲食佔六成，先從 每天一杯的手搖飲下手」這種 看得出有讀你資料 的建議。 （你們「溫室植栽專家系統」的 RAG 就是同一個道理——附上手冊段落再問。）

注意三件事：

  • 有了 api/ 資料夾，本機測試要改用 npx vercel dev 啟動 （純靜態的開法看不到後端），部署也要用 Vercel。
  • 金鑰在 Vercel 上用 npx vercel env add GROQ_API_KEY 設定， 或叫 AI 帶你在網頁後台設。
  • system prompt 裡的「不知道就說不知道」是上半場講的 降低幻覺 的第一道防線。

做完之後對照一下：你們「溫室植栽專家系統」的 /api/ask 是同一套骨架， 差別是它把「附資料」這步自動化了——RAG 自動從栽培手冊撈相關段落 塞給模型（上半場 Part 08），而你這裡是手動把支出統計附上去。

5.3.4. 一定要用 Vercel 嗎？

不一定。先分清楚你屬於哪一種：

  1. 用的是免金鑰 API （本課的 Open-Meteo、Frankfurter）→ 完全不需要後端 ， 前端直接 fetch，網站拖上 Netlify Drop 就上線了。
  2. 用的是有金鑰的 API → 才需要一個「藏金鑰的後端」。選項由簡到繁：
方案 需要什麼 特色
Val Town 只要瀏覽器＋帳號 在網頁上寫一小段函式，存檔就有網址，最無痛
Cloudflare Workers npx wrangler deploy 一個檔案就是一個後端，免費額度大
Vercel（CLI 直推） npx vercel ，email 登入 不用接 GitHub ——CLI 從資料夾直接部署

常見誤會：「用 Vercel 要先學 GitHub」——不用。在專案資料夾執行 npx vercel 登入後就直接上線；接 GitHub 只是加值功能（push 自動重新部署）， 之後想要再加。課堂上一律叫 AI 代勞： 

用 npx vercel 幫我把這個專案部署上去，不要走 GitHub，一步一步帶我做。

5.4. 可以直接玩的免費 API

API 用途 金鑰？
Open-Meteo 天氣預報 不用
Frankfurter 匯率（歐洲央行資料） 不用
BigDataCloud 經緯度 → 地名（反查） 不用
政府資料開放平臺 台灣各種公開資料 多數不用

6. Web 的上架

做好的網站只在你電腦裡＝不存在。上架後有網址， 手機、評審、家人都打得開 。

6.1. 三條路

方案 難度 適合 備註
Netlify Drop ★（拖拉） 純前端、今天就要看到成果 免註冊可先試，網址隨機
GitHub Pages ★★（要 git） 純前端、想要穩定網址＋版本紀錄 免費、跟 git 存檔點整合
Vercel ★★ 有後端 serverless（串金鑰 API） 你們的「溫室植栽專家系統」就在這裡

判斷法： 只有 HTML/CSS/JS → 前兩個都行；有 api/ 資料夾（後端）→ Vercel。

對照你的零用錢程式，上架分兩個階段：

  • 做到 Step 5（純前端，還沒有 api/ ）→ 走 最簡單的 Netlify Drop ， 拖上去兩分鐘就有網址。
  • 加了「省錢小軍師」（有 api/ ）之後 → 改用 npx vercel ， 因為 Netlify Drop 跑不了你的後端。

6.2. 實作 A：Netlify Drop（兩分鐘上線）

  1. 開 app.netlify.com/drop
  2. 把整個 money-app 資料夾拖進網頁
  3. 得到一個 xxx.netlify.app 網址 → 用手機開開看！

6.3. 實作 B：請 AI 幫你上 Vercel

上架這種瑣事正是 vibe coding 的甜蜜點——流程它都會： 

幫我把這個專案部署到 Vercel，我還沒有帳號，一步一步告訴我要做什麼。

它會引導你裝 Vercel CLI（ npx vercel ）、登入、部署。 需要你自己動手的只有「用瀏覽器登入帳號」這種它碰不到的步驟。

6.4. 上架前的檢查清單

  • [ ] 網頁裡沒有任何 API 金鑰、密碼、個資（ 上架＝全世界都看得到 ）
  • [ ] 手機實際打開測過（不是只有電腦）
  • [ ] 需要定位／相機的功能，只在 https:// 網址下才能用（上架平台都自帶 HTTPS， 但自己電腦用 IP 分享給手機測試時會失效——你們 App 的 README 裡踩過這個坑）

6.5. 課後挑戰

  1. 加「刪除／修改一筆支出」功能（記錯了總要能改）。
  2. 加「本月 vs 上月」比較（提示：localStorage 依月份分開存）。
  3. 把網站上到 GitHub Pages，並讓 AI 教你看 commit 歷史。
  4. 進階：讓省錢小軍師記得你的「存錢目標」，建議往目標靠攏。

7. 進階：Skill——把 AI 變成特定領域的專家

7.1. 什麼是 skill

還記得 Step 0 的班規檔 GEMINI.md 嗎？它是「每次啟動都讀」的長期規則。 Skill 則是「需要時才翻的工具書」 ：一個資料夾，裡面放一份 SKILL.md 說明書（教 AI 某件專門任務的完整做法），還可以附腳本、範本等工具。

比較 班規（GEMINI.md） Skill
讀取時機 每次啟動都讀 任務相關時才載入
內容 通用規則（語言、風格） 專門任務的完整做法（步驟＋工具）
比喻 貼在牆上的班規 書櫃裡的工具書

7.2. Skill 如何運作

關鍵機制叫 漸進式載入 ：AI 平常只記得每本工具書的 「書名＋一句話簡介」（ SKILL.md 開頭的 name 和 description）； 當你的任務對上某個簡介，它才把整本翻開來照著做。 所以裝一堆 skill 不會拖慢平常的對話——沒用到的只佔一行目錄。

翻開之後，AI 就照 SKILL.md 裡的步驟執行：可能是一套操作流程、 一個檢查清單，或直接呼叫資料夾裡附的腳本。

7.3. 哪裡找得到現成的 skill

  • 官方倉庫 ：github.com/anthropics/skills——Anthropic 維護的 skill 集，最實用的是文件處理系列： docx 、 xlsx 、 pptx 、 pdf （讀寫 Word／Excel／簡報／PDF）。
  • 社群collections ：GitHub 搜「claude skills」或「awesome claude skills」， 有大量社群整理的清單。
  • ⚠ 安全提醒：skill 是 給 AI 的指令 ，裝之前打開 SKILL.md 看一眼內容 ——跟不亂裝瀏覽器外掛同一個道理。

7.4. 如何安裝

安裝＝ 把資料夾放到工具會找的位置 ，沒有安裝程式：

工具 skill 資料夾位置
agy 專案裡的 .agents/skills/
Claude Code 專案 .claude/skills/ 或全域 ~/.claude/skills/

以官方 docx skill 為例： 

git clone https://github.com/anthropics/skills
mkdir -p .agents/skills
cp -r skills/skills/docx .agents/skills/

（懶人法：直接叫 AI 代勞——「幫我把 anthropics/skills 的 docx skill 裝到這個專案」。）

7.5. 如何使用

  • 自動觸發 ：任務對上 skill 的 description 就會自己用—— 「幫我摘要 報告.docx 的重點」。
  • 點名使用 ：明講「用 docx skill 幫我……」。

用前後差在哪，見本節最後的參考對話。

7.6. 如何自建 skill

最小的 skill 就是一個 SKILL.md ，兩個部份：開頭的 frontmatter （name＋description， description 決定什麼時候被觸發 ，要寫「何時用」）， 加上內文的做法步驟。

拿零用錢程式舉例： 

---
name: spending-report
description: 當使用者要求「產生支出報告」或「本週花費總結」時使用。
---
# 支出報告產生流程
1. 讀取 index.html 裡 localStorage 的支出資料結構。
2. 依類別彙總本週金額，算出佔比與前一週的差額。
3. 用固定格式輸出：總支出、前三大類別、一句話建議。
4. 語言一律繁體中文，金額加千分位。

放進 .agents/skills/spending-report/SKILL.md ，之後只要說 「產生支出報告」，AI 就會照這套固定流程做—— 把你調教好的做法固定下來，不用每次重新教 ，這就是 skill 的價值。

訣竅：skill 也可以 vibe 出來——把你剛才手把手教 AI 的流程， 叫它自己封裝：「把剛才產生報告的做法寫成一個 skill，存到 .agents/skills/」。

7.7. 參考對話：沒有 skill 也能讀 docx，為什麼還要裝？   noslide

一段真實的問答，把「要不要裝 skill」的判斷講得很清楚：

問：沒有 skill 的話，你能讀 docx 的內容嗎？

答：可以。 .docx 其實是壓縮包（XML 結構），我可以用內建的指令執行 能力，臨時寫 Python（ zipfile 解析 word/document.xml 或 python-docx 套件）把文字、表格抓出來。

問：那我為什麼還要裝 anthropics/skills 的 docx skill ？

答：差別在「純文字抓取」和「專業排版／完整處理」：

功能面向 無 skill（臨時抓純文字） 裝了 docx skill
讀取深度 只抓得出散落的純文字 完整還原標題階層、表格結構、清單與樣式
圖文與附件 忽略圖片、頁首頁尾與註腳 支援圖片、頁首頁尾、目錄與頁碼
批註與修訂 讀不到批註與修改紀錄 支援修訂追蹤（Track Changes)與批註
編輯／修改 難（直接改 XML 容易弄壞檔案） 保留原樣式與範本做精確替換
從零生成 只能產出 Markdown／純文字 生成排版完整的專業 .docx

一句話總結： 只是要「讀懂某段寫什麼」，不用裝 ；要處理表格、改格式、 讀修訂紀錄、或自動產出正式的 Word 報告， skill 才是那位排版師 。

8. 進階：先寫規格，再讓 AI 動手（SPEC.md）

8.1. 先補一點軟體開發常識

真正的軟體團隊 不是坐下來就開始寫程式 。業界的標準流程長這樣： 

需求（要解決什麼問題）→ 規格（具體要做什麼）→ 實作（寫程式）
→ 測試（有沒有寫對）→ 驗收（是不是當初要的）

其中「規格」（specification，簡稱 spec）是一份白紙黑字的文件， 等於 客戶和工程師之間的合約 ：要做什麼、不做什麼、怎樣算做完。 沒有規格的專案，最後一定變成「我以為你要的是這個」大戰。

8.2. 為什麼 vibe coding 也需要規格

今天的零用錢程式只有六步，你邊聊邊做沒問題。但專案一變大：

  • 講一句、AI 改一片，改到後來 連你自己都忘了當初要做什麼
  • 對話換過幾輪之後，AI 開始「失憶」、改錯方向、前後矛盾

解法就是把業界那套搬過來： 先把規格寫成檔案 ，AI 每次動手前都 對著它做——規格成了你和 AI 之間 共同的合約 ，吵架時翻合約就對了。

8.3. SPEC.md：五個欄位就夠

在專案根目錄放一份 SPEC.md ，以零用錢程式為例： 

# 我的零用錢管理程式——規格

## 1. 給誰用
高中生自己用，手機優先。

## 2. 功能清單
必要：記支出（金額/項目/類別）、本月總額、類別統計、每月額度與超支警示
加分：美金匯率換算、AI 省錢建議

## 3. 畫面與資料
單一 index.html；資料存 localStorage；類別固定五種。

## 4. 怎樣算做完（驗收條件）
- 新增一筆支出後，重新整理資料還在
- 輸入 -100、0、abc 會被擋下並提示
- 超支時額度區變紅
- 手機直向操作不用左右捲動

## 5. 不做清單
不做登入、不做雲端同步、不做多人共用、不裝任何框架與套件

兩個欄位特別講一下，這是軟體業的看家本領：

  • 「怎樣算做完」 ——業界叫 驗收條件 （acceptance criteria）。 寫得出驗收條件，代表你真的想清楚了；寫不出來，代表你自己 也不知道要什麼，AI 更不可能猜對。
  • 「不做清單」 ——防的是業界最有名的專案殺手 範圍蔓延 （scope creep）：做著做著「順便加個登入好了」「順便上雲端好了」， 順便到最後，原本三天的東西三個月都做不完。

8.4. 怎麼用

  • 動手前 ：「先讀 SPEC.md，再開始做第 2 項功能。」
  • 做完後 ：「對照 SPEC.md 檢查一遍，有沒有哪條驗收條件沒過、 有沒有做了不做清單裡的東西？」
  • 要改功能 ：先改規格、再叫 AI 照新規格改程式—— 永遠讓合約跟現實一致。

8.5. 跟你們的專題有什麼關係

比賽或專題的 企劃書 ，本質上就是一份 SPEC.md：給誰用、 做什麼、怎樣算成功、不做什麼。先在小專案養成寫規格的習慣， 之後寫企劃書就是把 SPEC.md 換件正式的衣服而已。

10. 結語：AI 放大的是人

學到這裡，你會發現兩種同學：

  • 盲信的 ：AI 說什麼都對，程式碼貼上就交——出了錯完全不知道從哪救。
  • 拒斥的 ：AI 寫的我看不懂，乾脆不信任，回去一行一行手刻。

Vibe coding 走的是中間那條路： 懂得驗收、懂得追問、懂得拒絕 。 需求是你想的、驗收是你把的關、方向是你定的——AI 只是把你的意志 放大幾十倍的執行力。

AI 會放大人的能力。而歷史上每一次技術變革， 取代人的從來不是工具，是把工具用得更好的另一個人 。 去當那個人。
